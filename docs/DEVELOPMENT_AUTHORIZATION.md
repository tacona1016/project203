# 개발 작업 사전 승인 범위

2026-11-03 사용자 지시. 대상은 `tacona1016/project203` 및 연결된 Supabase·Vercel 프로젝트다. 시스템과 도구의 실제 권한·승인 절차를 우회하지 않는다.

- 개발 목표에 필요한 파일 수정, 테스트, 오류 수정, 일반 commit/push, 브랜치·PR 생성, 안전한 충돌 해결과 CI/CD 확인은 사전 승인된 작업이다.
- 기존 데이터를 보존하는 신규 테이블·인덱스·함수·migration 적용, 보안을 유지하는 RLS 수정과 연동 검증은 사전 승인된 작업이다. 현재 스키마·migration 이력을 먼저 확인하며 기존 SQL을 일괄 재실행하지 않는다.
- 연결된 Vercel 프로젝트의 빌드·로그·환경 설정 확인, 필요한 오류 수정, 배포·재배포 및 실제 응답 검증은 사전 승인된 작업이다. 비밀 값은 출력하지 않는다.
- 이력 강제 변경, force push, 저장소/서비스 삭제, 운영 데이터 대량 삭제·파괴, RLS 완화, 도메인 소유권·과금 설정 변경은 별도 확인한다.
- 다른 작업자의 변경, 기존 데이터와 UUID를 보존한다. 실제 운영 콘텐츠에 가짜 회원·글·투표를 등록하지 않고 합성 테스트와 읽기 전용 운영 검증을 구분한다.
- 일반적인 승인 요청을 반복하지 않는다. 실제 도구에서 차단되면 우회하지 않고 완료한 범위와 남은 조치를 명시한다.

장시간 작업은 `docs/SESSION_HANDOFF.md`에 진행 상황·변경 파일·오류·다음 작업·검증 결과를 기록한다. 이 정책은 해당 프로젝트의 기존 지침 중 반복 승인을 요구하던 부분에 우선한다.
