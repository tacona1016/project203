# 최종 의사결정 기록

투표는 의견을 모으는 자료이고, 이 기록은 논의 후 **실제로 확정한 합의**다. 투표 결과와 다른 결정을 내려도 근거와 변경 이력을 함께 남긴다. 실제 합의 전에는 확정 공지로 등록하지 않는다.

## 기존 BOARD에서 사용

1. 회원 로그인 후 ADMIN에서 관리자 추가 인증을 완료한다.
2. BOARD의 **공지사항 작성**을 연다. 기존 작성 화면에서 게시글 유형을 **공지사항**으로 선택해도 된다.
3. 신규 공지 작성 화면의 **결정 기록 양식 넣기**를 누르거나 아래 본문을 복사한다. 작성 중인 본문이 있으면 교체 여부를 확인한다. 양식은 초안만 입력하며 자동 저장·고정하지 않는다.
4. 제목을 `[결정] YYYY-MM-DD · 결정 제목`으로 작성하고 대괄호 안을 실제 합의 내용으로 바꾼다. 날짜·담당자·일정은 합의된 값만 입력한다.
5. 현재 적용 중인 중요한 결정만 상단 고정한다. 결정이 대체되어도 삭제하지 않고 후속 기록을 연결한다.
6. 다음 분기 발표자료에서 관련 결정 공지와 투표를 함께 정리한다.

BOARD 본문은 일반 텍스트로 표시되므로 아래 양식은 Markdown 렌더링 없이도 읽을 수 있게 구성했다. 관련 투표와 공지는 실제 내부 경로나 전체 사이트 URL로 기록한다. 링크를 기입하는 것만으로 투표 상태나 데이터를 변경하지 않는다.

화면용 양식은 `lib/board/decision-template.ts`에서 관리한다. 양식의 항목을 바꿀 때 아래 복사본도 함께 맞춘다. 관리자 신규 공지에서만 버튼을 제공하며 기존 게시글·공지 내용을 자동 변경하지 않는다.

## 복사할 본문

```text
결정 제목: [확정한 결정 제목]
결정일: [YYYY-MM-DD]
상태: [확정 / 후속 결정으로 변경됨]
적용 분기: [예: 2026 Q4]

최종 결정 내용
[무엇을 확정했고 어디까지 적용하는지]
[확정하지 않은 범위나 추가 확인이 필요한 조건]

관련 투표
- [투표 제목] · [/polls/실제-투표-slug]
- 결과 확인 기준: [YYYY-MM-DD HH:mm, 한국 시간]
- 투표 결과와 최종 결정의 관계: [동일 / 추가 논의 후 조정]

결정 근거
- [검토한 정보와 선택 이유]
- [다른 안을 선택하지 않은 이유 또는 남은 쟁점]

담당자
- [담당자와 역할]

다음 행동
1. [구체적인 후속 작업]
2. [다음 확인 또는 논의]

목표 일정
- [작업별 목표일 또는 미정 사유]

추후 변경 사항
- [기록일] · [변경 내용과 이유] · [후속 결정 공지 경로]
- [아직 변경 사항 없음]
```

## 기록 운영 원칙

- 투표 종료와 최종 합의 확정은 별개다. 상시 투표는 결과 확인 시점도 기록한다.
- 확정 내용, 조건부 사항, 미정 사항을 구분한다. 담당자나 목표일이 합의되지 않았다면 임의로 채우지 않는다.
- 단순 오탈자는 기존 공지를 수정할 수 있다. 결정의 의미가 바뀌면 새 결정 공지를 작성하고 양쪽에 관련 경로와 변경 이유를 남긴다.
- 기존 공지의 내용 수정·삭제도 관리자에게 가능하다. 이 양식은 변경 불가능한 감사 장부가 아니다. 중요한 분기 결정은 Git으로 보관되는 MDX에도 정리하고 DB 백업을 유지한다.
- 관리자 공지 권한과 작성자 검증은 기존 API·DB RPC가 수행한다. 템플릿 적용을 위해 새 테이블·메뉴·권한은 추가하지 않는다.
